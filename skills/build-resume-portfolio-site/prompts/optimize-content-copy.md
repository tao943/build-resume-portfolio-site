# Optimize Approved Content

Read the content quality gate, writing-coach rules, STAR and impact rubric, and
ATS checklist before rewriting. Read the JD customization rules too when a JD
exists. Rewrite only the requested experience or project block and preserve
every factual value unless the user explicitly corrected it.

Review action, method, scope, result treatment, ownership, fact IDs, evidence
IDs, and supported JD relevance. Return one recommended version. Return an
optional stronger version only when it has its own fact and evidence links.
Move unsupported, inflated, or unmatched-JD alternatives to blocked claims.
When result evidence is unavailable, use a truthful qualitative fallback rather
than inventing a metric.

Write the block review into `reports/content-quality-review.json`. Show Original,
Recommended, Evidence, Why, and optional Stronger Version. Do not mark the copy
approved; wait for explicit conversational approval of the exact wording and
record whether the selected version is `recommended` or `stronger`.
