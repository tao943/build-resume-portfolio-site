# STAR and Impact Rubric

Use this rubric internally when reviewing a project or experience. It is a diagnostic tool, not a requirement to print four labeled paragraphs.

| Check | Question | Evidence required |
|---|---|---|
| Situation | What product, system, user, or constraint created the need? | Source text or user confirmation |
| Task | What outcome or responsibility did the user own? | Fact ID and ownership status |
| Action | What did the user design, implement, analyze, or coordinate? | Action plus method/tool evidence |
| Result | What changed, was evaluated, delivered, ranked, or recognized? | Metric, comparison, award, link, or confirmed qualitative result |

Score each dimension as `supported`, `partial`, or `missing`. If Result is missing, write a truthful qualitative outcome or ask one question; never invent an impact number. If Task or Action is missing, ask about the user's actual contribution before strengthening the verb.

For technical projects, accept these result types:

- benchmark or evaluation change;
- latency, throughput, queue, coverage, or error-rate evidence;
- delivered runnable feature or integration;
- reproducible workflow, test suite, or recovery mechanism;
- external award or reviewer/user adoption.
