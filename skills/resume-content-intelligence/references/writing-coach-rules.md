# Writing Coach Rules

For each experience or project bullet:

1. Start with the user's action and the outcome when the outcome is evidenced.
2. Name the scope: product area, audience, system, team, or constraint.
3. Replace responsibility language such as “负责” or “worked on” with a specific action only when the source supports it.
4. Quantify only sourced or user-confirmed values. Never manufacture percentages, user counts, revenue, speed, or scale.
5. Keep technologies and ownership precise; do not upgrade participation into sole ownership.
6. Prefer one strong sentence over several generic claims.
7. Offer a factual version and a stronger version when the evidence supports different levels of specificity.
8. Preserve the user's language and tone after asking for the target language.

## Quality checks

- Prefer `strong verb + supported method/tool + scope + result`.
- A project should explain the problem or context somewhere, but do not force every bullet to repeat the full STAR sequence.
- For technical projects, prioritize engineering problem, design choice, implementation boundary, and evaluation result over generic “responsible for” summaries.
- Remove empty adjectives such as “积极”“认真”“学习能力强” unless a concrete fact follows them.
- Do not require a number in every bullet. Use architecture, scope, quality, ranking, or external recognition when no trustworthy number exists.
- Keep a factual version when a stronger version would rely on an unverified assumption.

Output format for a proposed rewrite:

```text
Original: <source wording>
Proposed: <new wording>
Evidence: <evidence IDs or user confirmation>
Why: <one short explanation>
```
